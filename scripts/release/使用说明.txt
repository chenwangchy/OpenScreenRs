OpenScreen —— 把一台 Windows 的屏幕，共享给同一局域网里的另一台设备（电脑 / iPad / 手机）看
================================================================================

一、怎么用（30 秒）

  0. 最省事：直接双击 openscreen-rs.exe
     （会自动用 WebRTC 模式开始共享，并打开控制面板）

  1. 或者双击任意一个「启动-xxx.bat」来指定默认模式
  2. Windows 如果弹出防火墙提示 → 点「允许访问」（公用和专用网络都勾上更保险）
  3. 浏览器会自动打开控制面板（也可以手动打开 http://127.0.0.1:3032/）
     面板上可以随时改：传输方式、分辨率、帧率、码率
     改完点 Apply，然后在另一台设备上打开面板上显示的那个地址
  4. 画面出现后，鼠标指针是系统原生样式，位置是实时的
     想让对方也能操作这台电脑：面板上勾「允许观看端操作这台电脑」（见第三节）
  5. 关掉这个黑窗口就停止共享

  注意：控制面板本身也是网页，所以另一台设备（iPad / 手机）打开那个地址
        看到的同样是控制面板，可以在那边直接切模式、改分辨率。


二、默认画质：按屏幕原生分辨率分享

  三个启动脚本都不指定分辨率，也就是「屏幕多大就发多大」，不做任何缩放
  （例如 2560x1600 的屏幕就是 2560x1600，60 帧）。缩放会永久损失清晰度，
  所以默认不缩放；如果网络扛不住，可以自己降。

  控制面板里可以直接选：传输方式、共享哪块屏幕、分辨率（默认原生）、
  帧率 30/60/120、码率、H.264 profile。点「应用设置」后编码器立刻重启，
  不用重新双击脚本，也不用手动刷新观看页（它会自己重连）。

  关于「共享哪块屏幕」：程序优先用 GPU 的桌面复制（快）；某块屏不支持复制时
  会自动退回 GDI 抓屏（慢一些，但一定能抓），并且**按这块屏的真实位置和尺寸**
  去抓，所以多屏、缩放、4K 都不会错位。
  如果画面静止但鼠标在动（说明只有光标通道活着、视频流断了），把窗口里的日志发出来。

  不同方式的带宽大致是：

     WebRTC  2560x1600@60   约 20 Mbps   ← 推荐
     MSE     2560x1600@60   约 12 Mbps   （TCP，码率给低了会更糊）
     MJPEG   2560x1600@60   150 Mbps 以上（近乎无损，必须千兆有线）

  WiFi 上建议用 5GHz；2.4GHz 跑原生分辨率基本没戏。


三、远程控制（鼠标 / 键盘）

  默认是「只看不控」。要能操作，打开控制面板（http://127.0.0.1:3032/），
  在「远程控制」里勾上「允许观看端操作这台电脑」，然后：

    - 观看页右上角会从「只读」变成「控制已开启」
    - 在画面上移动 / 点击 / 拖动 / 滚轮 / 打字，都是直接作用在这台电脑上
    - iPad、手机上：手指点一下就是点击，按住拖动就是拖拽，双指滑动是滚动

  安全相关（重要）：
    - 这条通道**还没有密码**，请只在你自己信的局域网里开启
    - 想立刻断开：在运行窗口里输入 x 回车（控制面板上的勾会同步取消）
    - 关闭控制、或者对方页面关掉时，程序会把对方按住的键和鼠标键全部松开，
      不会留一个卡住的 Ctrl

  三个已知限制（都是 Windows 本身的做法，不是没写）：
    - UAC 提示框、以管理员身份运行的窗口，点不进去
    - 中文输入法的候选词打不进去；英文、数字、快捷键正常
    - 浏览器自己的快捷键还是归浏览器（Ctrl+W 照样关标签页）


四、三种启动方式怎么选

  启动-WebRTC(最低延迟).bat   ← 推荐。延迟最低（~30-60ms），UDP 传输
      同一个局域网、路由器没有屏蔽设备互访时用这个。
      如果画面一直不出来，看页面左上角状态：
        - "not connected ... may block UDP"  → 换 MSE 那个
        - "click to start"                   → 点一下画面即可
        - "connected" 但 0 fps               → 显卡编码器不兼容，换 MJPEG 那个

  启动-MSE(兼容性最好).bat     ← WebRTC 连不上时用。走 TCP，和网页同一条链路
  启动-MJPEG(不需要显卡).bat   ← 不需要 ffmpeg，但依赖 DXGI 桌面复制
      带宽极高，建议千兆有线。

  注意：MJPEG 用的是程序内置的 DXGI 抓屏，**没有软件回退**；
        WebRTC / MSE 用的是 ffmpeg，抓屏失败会自动退回 GDI（较慢但一定能抓到）。


三之二、如果画面全黑 / 编码器报错

  窗口里如果出现 "the encoder stopped" 或 "Function not implemented"，
  说明这台机器的硬件编码或桌面复制不可用。程序会自动依次尝试：
      NVIDIA(NVENC) → Intel(QSV) → AMD(AMF) → Windows 自带(MediaFoundation)
  并在桌面复制失败时自动退回 GDI 抓屏。

  仍然不行时，可以手动强制 GDI：
      双击 .bat 之前先在本目录打开命令提示符，输入
          set OPENSCREEN_CAPTURE=gdi
          (回车后再运行 .bat)

  再不行就换「启动-MSE」，它避开了 WebRTC 的 UDP 协商，只走 TCP。

  提示：校园网 / 公司网常常禁止设备之间互访，那种网络下 WebRTC 和 MSE 都可能连不上。
        最简单的办法是手机开热点，让两台设备都连热点。


五、想要更高帧率（120Hz 屏幕）

  手机/平板是 120Hz 屏时，把 .bat 里的 --fps 60 改成 --fps 120，码率建议同时提到 30000。
  原生分辨率 + 120 帧对带宽要求翻倍。


六、常见问题

  Q: 打印出来的地址看着不对（例如 198.18.x.x、100.x.x.x）？
     A: 程序会自动跳过虚拟网卡（代理软件的 TUN 网卡、WSL、VMware 等）并挑出真实的局域网地址。
        如果还是不对，说明本机有多张网卡，窗口会额外打印 "other addresses on this machine"，
        把里面另一个试一下。
        也可以这样查：在运行本程序的机器上打开命令提示符，输入 ipconfig，
        找物理网卡（以太网 / WLAN）的 IPv4 地址，用它访问，例如：
            http://192.168.1.23:3032/
        服务端监听所有网卡，所以任何本机地址都能连。

  Q: 另一台设备打不开网址？
     A: ① 防火墙没允许（重新双击 .bat，点允许）
        ② 用错 IP 了 —— 窗口打印的那行才是当前可用的地址
        ③ 两台设备不在同一个局域网

  Q: 画面是黑的，但状态栏有数字？
     A: 状态栏里如果是 0 fps，说明没有画面数据。先看黑窗口里的报错，
        常见原因是显卡不支持硬件编码；换成「启动-MJPEG」最稳。

  Q: 画面卡 / 花屏？
     A: 原生分辨率对带宽要求高。降低码率不解决问题时应降低分辨率：
        在 .bat 的 serve 后面加 --height 1080（或者 1440）。

  Q: 画面糊？
     A: 提高码率，例如把 --bitrate 20000 改成 30000。

  Q: 勾了远程控制，点了没反应？
     A: ① 观看页右上角应该显示「控制已开启」；还是「只读」说明面板上没勾上（或勾的是别的窗口）
        ② 对面打开的是管理员权限的窗口（UAC 那条），注入不进去，这是 Windows 限制
        ③ 中文输入法打不出候选词，先用英文 / 数字试

  Q: 担心安全？
     A: 只有同一局域网内、知道这个网址的人能看到画面；没有任何数据发到互联网上。
        远程控制是默认关闭的，只有你在面板上勾了才生效。
        关掉窗口即停止共享。


七、系统要求

  - Windows 10 1803 或更高（需要 DXGI 桌面复制）
  - 不需要安装 .NET、Java、Python、Visual Studio 或 VC++ 运行库
    （exe 已静态链接运行时）
  - 浏览器端：Chrome / Edge / Safari 较新版本即可
